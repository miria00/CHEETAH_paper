 CHEETAH LP v5           

{\small\sffamily\color{accent} CHEETAH $\cdot$ cumulative master program}


The single linear program behind every number in the paper. It picks one chip per workload jointly with every admitted library mapping, buffering depth, residency, recomputation, memory placement, numeric format and reuse transform. All of these are selectors of one root program; branches only fix root selectors to tighten bounds. Every set, parameter, variable and constraint is written out below and tied to the code family that builds it. Speculative decoding is pinned off for now.

 

{\small\ttfamily 2026-09-22 $\cdot$ built on Plan 1 (\texttt{cheetah\_joint/joint\_lp.py}, \texttt{run\_e2e.py}) $\cdot$ 12 workloads: Llama-1 13B, 65B $\cdot$ Llama-3 70B $\cdot$ DeepSeek-V3 $\cdot$ SD-1.5 UNet $\cdot$ EfficientNet B1--B7}

   
\section*{01\quad Decisions this program encodes}
 
\begin{decisions}
 
\item \textbf{One root program} Every admitted choice is a selector of one root LP, including weight format, KV format and the DeepCache interval, eq. (53). Branches fix root selectors to tighten bounds and recover designs. A test checks that fixing the root reproduces each separately built branch. Single-family runs are for debugging only.
 
\item \textbf{One chip per workload} No chip shared across scenarios, no multi-device parallelism.
 
\item \textbf{Speculation pinned off} Its rows are written out, eq. (51), including the MoE expert-union verification traffic. The selector is fixed at K = 0.
 
\item \textbf{Contract fixed} Batch, prompt, output length, KV bins and shared-prefix structure come from the workload contract. Batching is not a decision.
 
\item \textbf{Quality through evidence} A format or approximation can be selected only if the accuracy menu admits it for that model, eq. (47). A combination needs joint evidence or has to fit the tolerance budget, eq. (46).
 
\item \textbf{Baselines named for what they are} The \emph{TPU-v3 resource-matched tiled proxy} (256 $\times$ 16$\times$16 tiles, 128 KiB slices, HBM 900) is a feasible point of v5. \emph{Baseline A} is FAST's recipe scaled up from an 8$\times$8 reference mapping. Neither is topology-faithful (2 cores $\times$ 2 MXUs of 128$\times$128, vector units, BF16), so a claim about an unchanged TPU-v3 needs a third, faithful model.
 
\item \textbf{Same numerical contract} Every comparison states its datatype. Our runs are W8A8 on both sides. A FAST comparison needs BF16 on both sides; switching quantization off is not enough.
 
\item \textbf{Monotone incumbents} Every earlier-stage design is evaluated as a candidate, so v5's U $\le$ the U of every earlier stage.
 
\item \textbf{Scenario contracts are workloads} Shared prefixes apply only where the contract declares them; \texttt{\_\_prefix25} is its own workload. Chunked prefill is a steady-state serving workload measured in time per batch turnover, as its contract says. It is not a branch of fixed-batch latency, because a sequence cannot decode before its own prompt is done.\hfill\badge{newc}{assumption}
 
\item \textbf{Two admission columns} Headline: v5 with every admitted family. Second: the same v5 with exact families only, because FAST excludes quantization. Both are complete cumulative solves.\hfill\badge{newc}{assumption}
 
\end{decisions}

\section*{03\quad The full program}
 
\subsection*{3.0\quad Conventions}
 
\begin{itemize}
 \item Time is in ms. $\mathrm{TS}=10^6$ cycles, which is 1 ms at 1 GHz. Bytes divided by GB/s gives ns, and dividing by $\mathrm{TS}$ gives ms.
 \item Every selector ($\alpha,\allowbreak{}m,\allowbreak{}\nu,\allowbreak{}\theta,\allowbreak{}z,\allowbreak{}y,\allowbreak{}\mu,\allowbreak{}q,\allowbreak{}\chi,\allowbreak{}\upsilon,\allowbreak{}\psi$) is continuous on $[0,\allowbreak{}1]$. Integrality comes back through recovery, and the gap certifies it.
 \item A product of a selector with a menu constant is written as disaggregated copies (a hull), which is exact at integral selections. A reciprocal of a continuous resource is a perspective tangent cut, which is a valid lower bound.
 \item The monospace label under each row is the \texttt{C.fam\_in}/\texttt{C.fam\_eq} family name in \texttt{joint\_lp.py}. \badge{newc}{v5} marks a row or term that is new.
 \item Release on is the general form. With release off, $p^{\rm rd}_{e,\allowbreak{}\ell}=p^{\rm hd}_{e,\allowbreak{}\ell}=p_e$ for every $\ell$.
 
\end{itemize}

\subsection*{3.4\quad Objective}
  
\eqgroup{Main solve}
 
\begin{center}\adjustbox{max width=\textwidth}{$\displaystyle \min\quad \underbrace{\sum_{i\in\mathcal O} r_i\,T_i}_{\text{task latency}}\;+\;\varepsilon_A\,\mathfrak A\;+\;\varepsilon_F\Big(\sum_{\gamma,\rho}b_\rho\,\frac{S_\gamma}{10^9}\,g_{\gamma,\rho}+C_{\rm st}\Big)\;+\;\varepsilon_R\sum_{e\in\mathcal E}\sum_{\ell\le L_e}\sigma_e\,p^{\rm hd}_{e,\ell} \qquad(0) $}\end{center}
 
\begin{center}\adjustbox{max width=\textwidth}{$\displaystyle \varepsilon_A A_{\rm cap}+\varepsilon_F\,\bar C_{\rm fast}+\varepsilon_R\sum_e\sigma_eL_e\ \le\ 10^{-4}\,L^{\rm Stage\,1},\qquad L_{\rm latency}=L_{(0)}-\Big(\varepsilon_A A_{\rm cap}+\varepsilon_F\,\bar C_{\rm fast}+\varepsilon_R\sum_e\sigma_eL_e\Big) $}\end{center}
 
\eqgroup{Minimal chip at the certified latency (after recovery, winning branch, modes pinned)}
 
\begin{center}\adjustbox{max width=\textwidth}{$\displaystyle \min\quad\mathfrak A\qquad\text{s.t. (1)–(47) with the recovered modes pinned},\qquad \sum_{i}r_i\,T_i\ \le\ (1+\delta)\,U,\qquad\delta=10^{-3}\qquad(0\text{B}) $}\end{center}
 

Latency is the primary objective: LLM prefill plus every decode step at B = 32, SD's denoising steps under the DeepCache branch, and one CNN pass at batch 1. The $\varepsilon$ terms only break ties. The certificate stays a latency certificate, because the penalties' largest possible value is subtracted from the bound, and U is the exact latency of the recovered design. Then (0B) finds the smallest chip that keeps that latency to within 0.1\%, and that chip is the one reported.

\subsection*{3.14\quad Root, branches and certificate}
 
\begin{center}\adjustbox{max width=\textwidth}{$\displaystyle \beta=(a^\ast,\ t^\ast,\ \sigma,\ \sigma^{\rm KV}),\qquad L=\min_{\beta\in\mathcal B}\ L_\beta,\qquad U=\min\Big\{\mathrm{sched}\big(\mathrm{recover}(\mathrm{LP}_\beta)\big)_\beta,\ \mathrm{sched}(d):\ d\ \text{an earlier design still feasible in v5}\Big\},\qquad \mathrm{gap}=\frac{U-L}{U} $}\end{center}
 
\begin{itemize}
 \item \textbf{Root and branches.} The root is (0)--(56) with every selector free. A branch fixes root selectors: PE type, technology, program block, KV format. Branches cover the root's discrete domain, so $\min_\beta L_\beta$ is a valid bound, tighter than the root relaxation. Clock stays at $f_0$ by the dominance proof in (10).
 \item \textbf{Branch bounds.} An unsolved branch keeps a valid bound: the box-aware safe dual bound computed in original units from whatever dual vector the solver holds. That bound is valid for any dual vector once every column has finite bounds (the machinery already built for CORGI). A branch without one leaves L uncertified for that workload, and it is reported that way; it is never dropped from the minimum.
 \item \textbf{Recovery.} Enumerate the discrete choices jointly: program block, KV format, weight format per weight identity (41), features. Then take each op's argmax mode within that consistent choice, re-solve the continuous rest, and floor the tiles. The slice capacity follows from (7).
 \item \textbf{U comes from a schedule, not the LP's accounting.} The evaluator \texttt{sched} runs the recovered design on a timeline. The host link is a single FIFO server; each prefetch is released one op ahead and must finish before its consumer starts; staging occupancy is tracked over time; transfer, conversion and compute overlap only as the validated pipeline allows. Exact-lift, which lifts the design into every variable and checks every row, is a formulation-consistency check only. Timeloop replay of the top ops is the physics check.
 \item \textbf{Minimal chip.} (0B) finds the smallest chip for the winning branch and its recovered modes. It is not the smallest chip at that latency over all mappings.
 \item \textbf{Incumbents.} U $\le$ the v5 time of every earlier design that is still v5-feasible, compared on latency alone, without the $\varepsilon$ terms. That is not a claim that v5 beats every historically reported stage time.
 \item \textbf{Reported for every result.} U, L, gap and gates. Traffic split per phase (weights, KV, host, other). Delivered vs installed bandwidth. Separate comparisons against the tiled proxy, baseline A and (once built) the faithful TPU-v3 model, each under a stated numerical contract.
 
\end{itemize}
 
\subsection*{3.15\quad Size}
 

Per op, per branch there are $|\mathcal K_{a^\ast}|=15$ modes and $|\mathcal J|\le8$ bandwidth points.

 
\begin{itemize}
 \item \textbf{Columns:} about $15\,\allowbreak{}(7+8\,\allowbreak{}(1+n_{\rm cred})+|\mathcal U|)$, where $n_{\rm cred}\le7$ credit kinds.
 \item \textbf{Rows:} about $15\,\allowbreak{}(36+8+8\,\allowbreak{}n_{\rm cred}+6)$, dominated by the tangent rows (25) and (28).
 \item \textbf{Program blocks:} SD's DeepCache blocks double its op count in the root.
 \item \textbf{Measured reference:} the Stage 2 SD Winograd root, over 30 modes, was 878,108 rows $\times$ 380,004 columns and took 61 minutes.
 
\end{itemize}
 

\textbf{Mode dominance presolve, corrected.} Mode $k'$ removes $k$ only if all of the following hold:

 
\begin{itemize}
 \item both have the same PE type, \emph{the same buffering depth}, the same feature, format and transform requirements, and the same credit-eligible dataspaces;
 \item $D'\le D$, $Q'^{\bullet}\le Q^{\bullet}$ for every dataspace, $W'\le W$, $\vartheta'\le\vartheta$, $\beta'\ge\beta$, $X'\le X$.
 
\end{itemize}
 

Comparing $D,\allowbreak{}Q,\allowbreak{}W$ alone would delete a double-buffered mode that runs nearly twice as fast, because it has the same $D,\allowbreak{}Q$ and a larger $W$. A regression test guards against this.

\section*{08\quad Outer loop: a dual-guided implementation designer}
 

The LP answers "what is the best design among the implementations we can substantiate". The LLM answers "given what is expensive in that optimum, which implementation should we develop next". The LLM never sets MAC count, bandwidth, batch or budgets: those are LP decisions or contract constants.

\subsection*{What the LLM reads: \texttt{dual\_report}, computed in code}
 
\begin{itemize}
 \item \textbf{Contract and status:} model, task, numerical contract, limits and disabled families; primal and dual residuals in original units, L, U, gap.
 \item \textbf{Constraint semantics:} row family, op, phase, tensor identity and live interval for every priced row. Duals from the latency solve (0) are never mixed with those from the area solve (0B).
 \item \textbf{Priced opportunities:} the local value of a \emph{specified} change, $\widehat{\Delta V}=\nabla_\theta\mathcal L(z^\star,\allowbreak{}\lambda^\star;\allowbreak{}\theta)^{\top}\Delta\theta$, rather than a raw multiplier ranking. For storage, the time-indexed price of a tensor, $\sigma_e\sum_{t\in\mathcal I_e}\lambda^{(13)}_t$, shows which part of its lifetime competes for SRAM.
 \item \textbf{Robustness:} scores are compared across alternative dual solutions and small controlled re-solves, because degenerate optima have non-unique prices.
 \item \textbf{Library gaps and validation:} missing mappings and unsupported combinations; rejected proposals and why; $|\partial V/\partial\theta|\,\allowbreak{}\Delta\theta_{\rm unc}$ for influential coefficients that are assumed rather than measured.
 
\end{itemize}
 
\subsection*{What the LLM proposes, and how it enters}
 
\begin{itemize}
 \item \textbf{The proposal:} a concrete implementation or bundle (for example fused unpack, dequantize and compute with a stated layout and converter; a producer--consumer tiling that shortens an expensive skip's live interval; a new vector path or bank organization with its interface). It lists target ops, the price signals it answers, resource accounting, required hardware and the tests to run.
 \item \textbf{The block:} after verification it enters the versioned library as a block of variables and rows. The full root is re-solved with all hardware free, and the recovered design is run through \texttt{sched}.
 \item \textbf{Screening vs reward:} reduced cost $\bar c_j=c_j-a_j^{\top}\pi$ is only a screen. The reward is verified feasible latency, and a measurement that raises predicted latency still counts as a successful validation.
 
\end{itemize}
 
\subsection*{Certificate scope}
 

Bounds hold for the frozen library. The LLM finding nothing is not a stopping certificate. A larger universe is covered only by a verified pricing procedure: with a proved per-group pricing error $\epsilon_i$, $L_{\rm full}\ge D_{\rm restricted}-\sum_i\epsilon_i$ (the Hijazi et al. arrangement: learned proposals for speed, exact verification for the guarantee).

\section*{09\quad Outside v5, and why}
 
\begin{itemize}
 \item \textbf{Multi-device tensor or expert parallelism, prefill/decode disaggregation (DistServe), CPU offload of cold work (PowerInfer):} more than one device, so the one-chip rule excludes them.
 \item \textbf{Wafer-scale (WaferLLM):} outside the single-reticle area domain.
 \item \textbf{Batch as a decision:} it changes the measurement contract. It belongs in a separate serving study with arrivals and SLOs.
 \item \textbf{Architecture changes (GQA uptraining, MLA conversion):} model changes, not deployment choices. Each checkpoint is used as released.
 \item \textbf{PIM (52) and speculation (51):} written out, pinned, and stated as such in the paper.
 
\end{itemize}
